# Tendworks v0.5.0 – workflows started by hand (draft)

Draft notes for the next release, filled in as its changes land. Spec #130 (ADR 0028): a trigger binding of kind `manual` declares a workflow you start only when you decide, such as a review or a release, with the workspaces it may run in. Follow [docs/operator-guide.md](../operator-guide.md#manual).

## Before you update

- No migration and no change to existing configuration: `schedule` and `github-issues` bindings work as before.

## What changed

| Area | Change |
| --- | --- |
| `TriggerBinding` | new trigger kind `manual: {}`: never fires on its own. The manual trigger source is deployed with the server. |
| Firing | `POST /triggers/{name}/fire` (API token; optional body `{ "workspace": "<name>" }`) starts one run per workspace of the binding, or only in the named one, with the input `{ workspace, item }`, the binding as the run's origin, `trigger.fired`, and the firing recorded as the binding's last check. Each firing is a new item (`started by hand`, keyed by its time). Refused: `404` unknown binding, `409` suspended or not of kind `manual`, `400` a workspace that is not the binding's, `403` with the read-only token. |
| Trigger list | `schedule` and `nextExecutionAt` are optional in `GET /triggers`; a manual binding has neither. `tend trigger list` shows `-` for both; the web UI's Triggers page shows "by hand". |
| Contracts | `manualTrigger` in `contracts/schemas/trigger-binding.schema.yaml`; `fireRequest` and `fireResult` in `contracts/schemas/trigger.schema.yaml`; `POST /triggers/{name}/fire` in the control plane and trigger gateway APIs. |

## What you configure

1. Optionally add a binding with `trigger: { manual: {} }` to `triggers/` ([`manual`](../operator-guide.md#manual)), then `docker compose -f deploy/compose.yaml restart server`.
2. Fire it: `curl -X POST localhost:8080/triggers/<binding>/fire -H "authorization: Bearer $TEND_API_TOKEN"`.

## Known gaps

- Who fired a binding is not recorded; there is one shared API token until OIDC.
- `schedule` and `github-issues` bindings cannot be fired by hand.
