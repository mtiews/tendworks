# Tendworks v0.4.0 – notifications as subscriptions

Milestone 4 (spec #87, ADR 0026): notifications separate what happens from who wants to know. A notification channel only says how you are reached; subscriptions choose which events of a workspace (a project) or of the platform go to which channels, with which priority. New events tell you when a run starts and when the platform becomes degraded or recovers, and a heartbeat lets an external monitor alarm when the platform stops reporting. Follow [docs/operator-guide.md](../operator-guide.md#notifications).

## Before you update

- **v0.4.0 needs a fresh installation.** The store of human interaction changed in place: a notification may have no run (`platform.degraded`, `platform.recovered`), so `human_interaction.notifications.run_id` is nullable. No migration is added, because v0.3.0 was not in production. Start from a **fresh installation** ([Reset](../operator-guide.md#reset), then [Install](../operator-guide.md#install)); an existing store would refuse platform notifications.
- **Channels lose their event selection.** A `NotificationChannel` with `spec.events` or `spec.pushover.priority` is refused when the server loads the configuration. Move the priority to `spec.priority` and the events to a `Subscription`.
- **Without a subscription nothing is delivered any more.** Notifications are still recorded and listed (`tend notification list`, Notifications page), but a channel receives only what a subscription sends it.

## What changed

| Area | Change |
| --- | --- |
| Event catalog | per workspace: `run.started`, `run.completed`, `run.failed`, `approval.requested`; for the platform: `platform.degraded`, `platform.recovered`. A run without a workspace belongs to the platform scope. |
| `NotificationChannel` | holds `integration`, its settings and an optional default `priority` (-2 to 1); no `events`. |
| `Subscription` (new kind) | `scope` (`workspace: <name>` or `platform: {}`), `events` of that scope, `channels`, optional `priority`. Refused at load: unknown workspace or channel, an event outside the scope, an empty `events` or `channels`. |
| Delivery | one message per channel, however many subscriptions match, with the highest of their priorities (else the channel's, else 0). The delivery status is recorded per channel. |
| `run.started` | names the workflow, the workspace and the trigger origin; a tap opens the origin's link (e.g. the issue). |
| Platform health | the server checks the platform's components (the worker's included) about every minute; a change counts after two equal results in a row. |
| Heartbeat | `TEND_HEARTBEAT_URL` in `deploy/.env`: while `/status` is healthy the server calls it about every five minutes. Unset: no call. |
| Clients | `tend subscription list` and a read-only Subscriptions page in the web UI. |
| Contracts | `contracts/schemas/subscription.schema.yaml`, `platform.health-changed` in `contracts/events/platform-events.schema.yaml`, `GET /subscriptions` in the control plane API. |

## What you configure

1. Rename `notifications/phone.yaml.example` to `notifications/phone.yaml` (secrets as in v0.3.0).
2. Rename `notifications/subscription-playground.yaml.example` (a project's events) and, if you want to know whether the platform runs, `notifications/subscription-platform.yaml.example` (opt-in), and choose `events` and `priority`. Subscriptions of a project belong next to its workspace and triggers.
3. Optionally set `TEND_HEARTBEAT_URL` to the ping URL of a push monitor (healthchecks.io, Uptime Kuma; operator guide, [Heartbeat](../operator-guide.md#heartbeat-when-the-platform-itself-is-down)).
4. `docker compose -f deploy/compose.yaml up -d --wait`, then `docker compose -f deploy/compose.yaml restart server`.

## Known gaps

- The health check's state is kept in memory: after a server restart a degraded platform counts as healthy until a check fails twice.
- A failed delivery is not retried.
- Subscriptions address channels, not people; quiet hours and personal subscriptions wait for OIDC. Subscriptions are configured in the repository only, not in the UI.
- Pushover is the only channel besides `fake`.
